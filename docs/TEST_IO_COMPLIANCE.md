# Test IO Compliance & Operational Guidelines
**Platform Policy Alignment:** Test IO Community & Customer Code of Conduct  
**Version:** 1.0

---

## 1. External Platform Relationship

Test IO (`tester.test.io` / EPAM Test IO) is an external crowdtesting service with strict tester agreements, anti-fraud rules, and quality standards:

1. **Third-Party Status**:
   - `Test IO Agent Studio` is an auxiliary QA productivity tool. It is **not** endorsed by or officially affiliated with Test IO.
2. **No Platform Automation (Default Block)**:
   - Automated scripts must **never** browse, scrape, or perform actions inside `tester.test.io` or customer portals without written consent.
   - Bypassing platform invitations, auto-claiming test cycles, automated assessment solving, and auto-submitting bug forms are strictly forbidden.
3. **Tester Responsibility**:
   - All bug reports generated by the studio are formatted as `DRAFT` reports.
   - The human QA professional must review the steps to reproduce, verify the actual bug on real target devices, and manually submit the findings through the official Test IO interface.

---

## 2. Execution Modes and Compliance Mapping

| Mode | Allowed Use | Test IO Compliance Status |
|---|---|---|
| **COPILOT_MODE** | Parsing customer requirements, generating test scenarios, drafting bug reports, formatting reproduction steps | **Fully Compliant** (Operates as an assistive drafting tool) |
| **SUPERVISED_MODE** | Browser actions on authorized staging/demo targets with human confirmation per action | **Fully Compliant** (Human tester maintains 100% oversight) |
| **AUTHORIZED_AUTO_MODE** | Autonomous execution against verified authorized domains (e.g. Demo Testing Lab, internal staging) | **Compliant** on authorized targets only. Domain allowlist strictly blocks external platforms. |

---

## 3. Evidence Integrity Standards

Test IO requires high-quality, unmanipulated evidence:
- Every screenshot and video captured must originate from live browser/desktop execution.
- No simulated bug screens, mock logs, or synthetic pass/fail metrics may be presented as genuine test evidence.
- SHA-256 hashes are computed at the moment of capture to ensure chain-of-custody integrity.
